# Tedca OS — Security Audit (2026-07-12)

Read-only, authorized defensive audit of the live `tedca-os` app.
Target code: `server/src/`, `app/src/`, Dockerfile, ignore files.
Live: `https://tedca-os-production.up.railway.app` (login gate = `OS_PASSWORD`).

## Executive summary

Overall posture is **decent for a single-user internal tool** — every data/mutating/send route is behind `requireUser` or `requireWorker`, both use constant-time token comparison, SQL is parameterized throughout, path-serving routes are root-jailed, secrets are not committed (`.env` untracked, keystore written `0600`, `.dockerignore`/`.gitignore` exclude `server/data`), and the inbound-email→LLM auto-reply path is unusually well-hardened (data-framing + injection scrub + an outbound link/price allowlist screen). The **main real weakness is the front door**: the single shared password login has **no rate-limiting, lockout, or delay**, and a 64 MB JSON body is parsed on unauthenticated routes — so the one credential that unlocks the entire CRM, token stores, and a `replace`-mode DB wipe is brute-forceable and cheap to DoS. Secondary issues are missing HTTP security headers and session tokens passed in URLs/never expiring.

Verified live: `/api/health` open (returns `{ok:true}` only), `/api/stats` → 401 unauth, `/api/file?p=/etc/passwd` → 401, wrong login → 401, **no** HSTS/X-Frame/X-Content-Type/CSP headers, `X-Powered-By: Express` present, source maps **not** exposed (`.map` returns the SPA `index.html`).

## Findings (ranked)

| # | Sev | Title | Location | Attack scenario | Fix |
|---|-----|-------|----------|-----------------|-----|
| 1 | **High** | Login has no rate-limit / lockout / backoff | `server/src/index.js:137-155` (`/api/login`); no `rateLimit` anywhere in `server/src`) | The whole app is one shared `OS_PASSWORD`. An attacker can POST guesses to `/api/login` at full speed forever — no per-IP cap, no lockout, no delay, no captcha. A weak/medium password falls to an offline-speed online brute force. A valid token then unlocks all leads/emails, `/api/gmail/import-tokens`, `/api/smtp/import-inboxes`, `/api/settings` (can flip `test_mode`/`send_transport`/`paused`), and `/api/admin/import-data` with `replace:true` which **wipes and overwrites** `emails`+`leads`+`runs` (`index.js:677`). | Add IP-based rate limiting + exponential backoff/lockout on `/api/login` (e.g. 5–10 tries/min then temp block). Log/alert on repeated failures to Telegram. Ensure `OS_PASSWORD` is long/random. |
| 2 | **Medium** | 64 MB JSON body parsed before auth (unauth DoS) | `server/src/index.js:89` (`express.json({limit:"64mb"})` global) | The 64 MB limit (needed only for `/api/admin/import-data`) applies to **every** route incl. unauthenticated `/api/login`. Repeated large POSTs to `/api/login` force the server to buffer/parse up to 64 MB each before the 401 — cheap memory-exhaustion DoS, amplified by finding #1's lack of rate limiting. | Default a small limit (e.g. 256 KB) and apply `express.json({limit:"64mb"})` **only** on the import-data route. |
| 3 | **Medium** | Missing HTTP security headers | server responses (no `helmet`; grep found none) — verified live | Live responses have no `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`/CSP `frame-ancestors`. The dashboard is framable → clickjacking; no MIME-sniffing protection; no HSTS pin. `X-Powered-By: Express` also fingerprints the stack. | Add `helmet()` (or set headers manually): HSTS `max-age` + preload, `X-Content-Type-Options: nosniff`, `frame-ancestors 'none'`/`X-Frame-Options: DENY`, and `app.disable("x-powered-by")`. |
| 4 | **Medium** | Session tokens passed in URL query strings | `server/src/index.js:200` (`/ws?token=`), `index.js:1512-1513` (`/api/skills/file?token=`) | Auth tokens in query strings leak into proxy/CDN/Railway access logs, browser history, and `Referer` headers on any outbound link. A leaked token is a full session (see #5 — they never expire). | Authenticate media/WS via the `Authorization` header, or issue short-lived single-purpose signed URLs for file streaming instead of the long-lived session token. |
| 5 | **Medium** | Sessions never expire and can't be revoked in bulk | `server/src/index.js:112-143`, `db.js:132-139` (`sessions` table, no TTL) | Tokens are stored in SQLite with only `created_at` and are honored forever; there is no expiry, rotation, or "log out everywhere". A token captured once (via #4, a shared machine, or `sessionStorage`) grants indefinite access. | Add an expiry column + reject/prune tokens older than N days; provide a "revoke all sessions" action; rotate on password change. |
| 6 | **Low** | Wide-open CORS reflects any Origin on authed routes | `server/src/index.js:95-106` | Every route (incl. mutating/`DELETE`) reflects the caller's `Origin` and allows the `Authorization` header. Defensible today because auth is a Bearer token in `sessionStorage` (not a cookie) and `Allow-Credentials` is not set, so a third-party page can't ride ambient auth — but it needlessly widens the surface: any origin that ever obtains the token can use the full API from a browser. | Reflect only an allowlist of known origins (the Railway app URL + any trusted dashboards). |
| 7 | **Low** | Authenticated arbitrary-directory read of `meta.json` | `server/src/index.js:1178-1192` (`/api/posts/preview`) | `folder` is user-supplied and `path.join(path.resolve(folder),"meta.json")` is read with **no** `withinRoots()` containment (unlike `/api/file`). An authenticated user can read any `meta.json` anywhere on the host filesystem and have its `creative` field summarized back. Authed-only + fixed filename limits impact. | Apply the same `withinRoots()`/root-jail check used by `/api/file` before reading `folder`. |
| 8 | **Low** | Prompt-injection residual in reply concierge (well-mitigated; keep the backstop) | `server/src/replies.js:132-137` (`scrubInjection`), mitigated by `screenDraft` `146-162` | Inbound reply text reaches two LLM calls. `scrubInjection` only drops **whole lines** matching a fixed regex, so an injection payload on the same line as legitimate text survives into the prompt. Real exfiltration is blocked downstream by `screenDraft` (outbound allows only the `REACTIVATION_URL` link, blocks prices/commitments, caps ~75 words, one auto-reply per lead, legal/"are you a bot" escalate to human). Risk is low **only because** of that outbound screen. | Keep the outbound allowlist screen as the primary control (do not weaken it). Optionally strengthen `scrubInjection` and keep the strict single-URL egress filter. |

## Fix these first (top 3)

1. **Rate-limit + lockout `/api/login`** (Finding 1) — the single unauthenticated door to the entire system, currently unthrottled.
2. **Shrink the default JSON body limit; scope 64 MB to import-data only** (Finding 2) — removes the pre-auth memory-DoS amplifier.
3. **Add security headers via `helmet` (HSTS, nosniff, frame-ancestors) and disable `x-powered-by`** (Finding 3) — cheap, closes clickjacking/MIME/fingerprint gaps.

## Confirmed good (no action)

- All data/mutating/send routes gated by `requireUser`; worker routes by `requireWorker`; both compare tokens with `crypto.timingSafeEqual` (`index.js:122-191`).
- SQL is parameterized everywhere; the dynamic `INSERT INTO ${table}` in import-data uses a fixed table list and DB-derived, column-filtered keys (`index.js:658-668`) — not user-controlled.
- File streaming is root-jailed via `path.resolve` + `withinRoots`/`startsWith(root+sep)` (`index.js:1112-1124`, `1512-1515`); `/api/file?p=/etc/passwd` → 401/403.
- `_execFile` for the keyword-sheet reader uses an argument array with fixed paths — no shell, no injection (`index.js:1397`).
- Secrets not committed: `.env` untracked, no API-key patterns in committed `server/`/`app/`/`worker/` code, keystore + SMTP store written `0600` (`keys.js:80-82`, `smtp.js:37-38`), keys masked to last-4 (`keys.js:133-137`), `.dockerignore`/`.gitignore` exclude `server/data/` and `.env`.
- `SEND_DISABLED=1` kill-switch enforced in `pool.js:27`, `engine.js:920/961`, `hotleads.js` — dormant cloud instance can't send.
- Source maps not served in production.
